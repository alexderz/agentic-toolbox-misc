## 12am run: Omarchy A, Linux desktop for older iPads (watch)

- **What it is:** a community project (not an official Omarchy release) that installs an Omarchy-inspired Arch Linux
  ARM desktop, reworked for touch, next to iPadOS on Apple A-series iPads.
  [Iris note](https://github.com/alexderz/agentic-toolbox-misc/blob/main/iris/2026-11-16-steady-alex-bookmarks.md) ·
  [code](https://github.com/OrchardLinux/omarchy-a) · [hardware layer and `orchard` tool](https://github.com/OrchardLinux/orchard) ·
  [releases](https://github.com/OrchardLinux/omarchy-a/releases).
- **What we checked on GitHub:** repo created Oct 25, about 200 stars, latest release `v0.3.1` (Nov 15, built on
  orchard 0.3.1) with `SHA256SUMS`, a build receipt and a sigstore bundle. Licence: the `LICENSE` file is
  GPL-2.0-or-later (GitHub's API shows "NOASSERTION" because the repo also has a `NOTICE`); the same for `orchard`.
  `resize-apfs`, `m1n1` and the task manager are MIT.
- **How it works:** the iPad's boot ROM has an unpatchable exploit (A11 chips and older), which lets a host
  computer over USB in DFU mode start Pongo, then Asahi-derived m1n1, then orchard's Linux kernel. The installer
  (a self-contained `orchard-install.pyz` fetched by a `curl | sh` script) writes a boot partition and the root image
  into at least 9 GiB of space you first free with the separate Resize APFS tool (which uses palera1n). The desktop is
  Labwc/wlroots with QML shell pieces. On the iPad 6 and 7 the GPU runs through a PowerVR Mesa fork, and Firefox plays
  H.264 through the hardware decoder, but only with Firefox's media-decoder sandbox switched off. Supported device
  today: iPad 6 Wi-Fi (`iPad7,5`); the iPad 7 also gets GPU acceleration; everything else is experimental.
- **Risks, from the project's own text:** boot is tethered (after a cold restart Linux only starts with a host computer
  running `orchard launch`); no disk encryption; the boot exploit gives anyone holding the device full access; the
  image logs in automatically. The README says `sudo` asks for the install password, while the `v0.3.1` release notes
  still say "unrestricted passwordless sudo; no local access protection". The project tells you to use a dedicated
  test device. Storage changes can erase iPadOS data, so a full backup comes first.
- **What it would take here:** a spare iPad 6 or 7 that holds nothing anyone needs, a USB data cable, and any Linux
  or macOS laptop (nothing in the lab, no new service, no network exposure). It does nothing for model testing.
  One idea we looked at and rejected: an old iPad as a Linux wall panel. Tethered boot means every power cut needs a
  computer plugged in, and a browser in kiosk mode on iPadOS already does that job.
- **Verdict: watch.** A good piece of hardware hacking and worth trying only on a spare old iPad as a toy; never on an
  iPad someone uses day to day. Revisit if it gets untethered boot or a stable release. Nothing installed.

## 12pm run: Tencent Hy4 flash (watch: no open weights yet)

- **What it is:** Tencent's smaller, cheaper sibling of Hy4, announced Nov 16. Tencent lists 224B total parameters
  (64B of them Engram lookup memory), 12B active per token, text and image input, 1M-token context, hybrid attention
  plus LatentMoE, and a KV cache 1/24 the size of Hy3's. The post's "160B-N64B-A12B" reads as 160B of model plus
  64B of Engram. [Iris note](https://github.com/alexderz/agentic-toolbox-misc/blob/main/iris/2026-11-16-steady-alex-bookmarks.md) ·
  [Tencent page](https://hy.tencent.ai/research/hy4-flash) · [OpenRouter listing](https://openrouter.ai/tencent/hy4-flash).
- **What we checked:** Hugging Face has no Hy4 flash repo yet (searched the `tencent` org and "hy4"/"hy4-flash"; only
  Hy4-preview and its requants exist), so there is no licence, config or model card to read. Tencent says it plans
  to release the weights; no date given. It is live on OpenRouter as `tencent/hy4-flash` (one provider, Tencent itself,
  served in FP8, $0.044 per million input tokens and $0.176 per million output, tool calling and reasoning supported).
  On the engine side, stock llama.cpp already runs Hy4-preview (`hy_v4`, PR #28127) and has Engram-style memory
  loading from the DeepSeek V4.1 Flash work, so support may be close, but that is unverified until a `config.json` ships.
- **Local fit on paper (not measured):** about 224B weights at roughly 4.5 bits per weight is about 125 GB, inside the
  ~160 GB "experts in system RAM" tier across both GPUs; a ~3.5-bit quant would be about 100 GB. Only 12B active
  parameters and a very small KV cache make it a natural candidate for our multi-session, long-context agent target,
  if the quality holds up.
- **Verdict: watch.** Re-check Hugging Face on each run. When weights appear: verify the licence (territory clauses
  too), read the architecture, then a viability case (fit, speed and time to first token, retrieval near 100K, the
  quality stage, then an agent test). Testing is paused for the port work anyway, so this goes to the backlog, not
  the queue. A hosted OpenRouter run is also possible and cheap, and is deferred to the backlog for the same reason.
