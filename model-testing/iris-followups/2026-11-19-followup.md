### Strata v0.2.16: Strata's own engine code (tech update)

- **What it is:** a new release of [Strata](https://github.com/Niko1221/Strata) (MIT), the local inference app and
  engine that serves our current daily-driver model (an Orca Flash-Next fine-tune, on Strata 0.2.15 since Nov 16).
  Release [v0.2.16](https://github.com/Niko1221/Strata/releases/tag/v0.2.16), commit `64524fb9`, published
  2026-11-18 21:57 UTC, 724 commits after v0.2.15. Engine and control program are both 0.1.62.
  Bookmarked post: https://x.com/coldniko/status/2123202426609999937
- **What we checked (GitHub, at the tag):**
  - **Engine code.** llama.cpp's MMQ prompt kernels are gone from the tree. Every CUDA build compiles Strata's own
    prompt kernels. ggml is still there for some CPU paths, but now vendored in `engine/third_party/strata-ggml`, at
    the same llama.cpp commit (`3cf03257`) as 0.2.15, so nothing is downloaded at build time.
  - **Same answers?** Upstream reports the same tokens as 0.2.15 on its 10 test prompts on six GPUs (RTX PRO 5000,
    P100, R9700, Arc A750, M5 Max, Strix Halo). Neither of our cards (RTX 3090, V100) is in that list, so token parity
    on our hardware is unproven.
  - **Speed claims that touch us:** a 26,000-token prompt on a Tesla V100 went from 17.5 s (engine 0.1.58) to 15.1 s.
    There is no RTX 30-series number in the notes.
  - **Server behaviour.** The `undeclared_tool_calls` setting (`text` or `call`) still exists in the server, so our
    `call` setting carries over. The new "a tool call that cannot run no longer ends the turn" fix is in Strata's own
    chat agent, not in the API server our harnesses use.
  - **Build layout moved.** Top-level folders are now `engine/`, `app/`, `terminal/`, `docs/`, `tools/`. The server is
    `terminal/serve/server.py`; the engine builds with `cmake -S engine`. Upstream ships an official source-build
    Dockerfile (`tools/docker/Dockerfile.src`) that covers a CUDA 12 build for older cards including the V100 (sm_70).
    Our own build recipe assumes the old layout, so it needs rework before it can build this tag.
  - **Ready-made binary:** `strata-engine-0.1.62-linux-x86_64-cuda-cuda12.tar.gz` (sha256 `450abcbd…c4d7`) is
    published with the release, an alternative to a source build.
- **Verdict: relevant; qualify it.** It is the engine of our daily driver, the kernel change is big enough that our
  own numbers can move either way, and the V100 prompt speedup is directly useful. The standard check is an A/B on the
  daily-driver model: same flags and power cap as the 0.2.15 production serve, comparing tokens/s, time to first
  token, long-prompt prefill, retrieval near the full context and token agreement with 0.2.15.
- **Started:** nothing yet. The GPU host has been offline since the evening of Nov 18, and its 24 GB card is in use
  for the daily-driver test suite when it is up. The qualification is handed to the lab owner (build recipe rework,
  then the A/B in a gap the testing side grants). Results will be added here when they exist.
