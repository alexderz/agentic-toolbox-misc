Source: [Iris's bookmark note](../../iris/2026-11-22-steady-alex-bookmarks.md), [post](https://x.com/JacksonAtkinsX/status/2124165896948347118), [upstream fork](https://github.com/realugbun/llama.cpp/tree/2eb2530ec4da95453e8ea7d68f937da174dfe799).

**Verdict:** a relevant engine qualification candidate, especially for the V100. This is a source-audited opportunity, not a local speed result. No weights, builds, case IDs or GPU tests started in this intake. The existing V100 maze run and the 3090 daily driver were left alone; the old whole-GPU queue remains paused.

### What we checked

- MIT licence, branch `inkling2-speed`, pinned head `2eb2530ec4da95453e8ea7d68f937da174dfe799`. No published releases or binary assets. Its exact upstream base is `e50c254a22c590c9d2a60db86690d48d42497e2b`: four code commits followed by four documentation/media commits, not four commits total. [Immutable comparison](https://github.com/realugbun/llama.cpp/compare/e50c254a22c590c9d2a60db86690d48d42497e2b...2eb2530ec4da95453e8ea7d68f937da174dfe799).
- The code actually adds normalized depth-state reuse, graph scheduling to make operation chains contiguous, eleven CUDA fusion variants, and a narrow-row padding optimization. The new fusion code and tests are present, not just a benchmark chart.
- Source inspection found no unconditional sm_80-only requirement in the added kernels. Both sm_70 and sm_86 are plausible **CUDA 12** targets; compilation and native target coverage remain unverified. CUDA 13 is not a V100 build path.
- No new disk KV/session-persistence default appears in this delta. Existing optional file caches and logging are separate inherited features, not an excuse to enable them.

### What the speed claims mean

The author's README reports **V100 Q4_K_XL decode +59–68%** and **1.6–4.9× pp512 throughput** at increasing context depths, with full GPU offload, flash attention and **F16 KV**. Its 5060 Ti IQ1_S rows report +37–39% decode and 2.0–4.1× pp512 throughput. These are short `llama-bench` measurements; pp512 at 128K context depth does **not** measure the total time to ingest a fresh 128K prompt. Time to first token is not supplied. The largest depth on each card uses ubatch 256 because 512 runs out of memory on both builds.

These claims do not predict our V100's Mainline_Support UD-Q8_K_XL with Q8 KV, or our 3090's Maya engine. In particular, this is not evidence that the fork beats the already-qualified Maya path on the 3090.

### Correctness is still a measurement, not a slogan

The added backend-chain tests compare against unfused CPU operations with numerical tolerances. The code carefully preserves rounding/reduction order in several paths, but an alternate MIX path and the README acknowledge numerical differences. The author's nonzero Kullback–Leibler divergence figures are useful evidence to investigate, not a bitwise-identity proof. We found no attached GitHub check runs on the pinned head or its four code commits. The README's 20,882 passing tests are an attributed third-party AMD/HIP report, not our CUDA result.

The fusion dispatcher and padding change are not restricted by a model-architecture gate, so “other models unaffected” is not an isolation guarantee enforced by the source.

### What it would take here

Our V100 deployment uses mainline b12622 and **Mainline_Support UD-Q8_K_XL**. The fork inherits the merged NVFP4 loop-scale correction, [llama.cpp #32704](https://github.com/ggml-org/llama.cpp/pull/32704). Older root-layout Unsloth files that need b12588 are a different engine/weight pair; a matching quant label is not enough to swap them.

Next action is with the lab's serving owner: build the exact upstream base and fork with the same CUDA 12 compiler/runtime and explicit `70;86` targets, including the added backend tests (the stock server Docker target disables them). Then stage a separate candidate and compare in a granted V100 test boundary, using the **same existing verified weights**, native reasoning controls, Q8 KV, context, batch/ubatch, cache warmth and power policy. Report sustained short/deep decode, full cold-prefill latency/time to first token, actual free VRAM, retrieval, tools and an image check. No new service, network exposure or weight download is required. No adoption or GPU slot is claimed by this intake.
