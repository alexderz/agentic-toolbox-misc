## T3 Tots v1.4.34: watch, not installed

Iris's 4pm run, unfiled folder, from [a post by @Deepusleepy](https://x.com/i/status/2121301170836971983).
Model Master's intake run, Nov 13 afternoon (Central time).

- **What it is:** [Deepusleepy/t3-tots](https://github.com/Deepusleepy/t3-tots) (MIT, created Oct 15, about 150
  stars), an unofficial chat companion for [T3 Code](https://github.com/pingdotgg/t3code). It is skills plus a
  few scripts: thread status, waiting items, new threads, answers, and optional phone notifications. The
  release Iris cited is [v1.4.34](https://github.com/Deepusleepy/t3-tots/releases/tag/v1.4.34), tagged Nov 13
  at commit `4044abaa`, not a pre-release. The tag ships no binaries. Install is a source archive or a clone
  of the tag, and every file is checked against that tag's `manifest.json`.
- **How it works:** three tools, all local unless you turn the listener on.
  - `t3q.py` opens T3 Code's database read-only. No token.
  - `t3ctl` talks to T3 Code's local websocket on `127.0.0.1`. That API is internal and not stable. A token,
    if you agree to one, sits next to the scripts, lasts 90 days, and is never printed. With no token the
    tools stay read-only. An approval is refused unless you passed a flag that says you approved that one
    request.
  - `t3listen` is optional. It POSTs live events (a question opened, a run finished, failed or cancelled) to
    a webhook you set up. That is the only outbound send. Approvals are off unless you turn them on.
  T3 Code now has an official MCP server and a `t3 thread` command. The README says those still do not cover
  permission approvals, live events to a webhook, resuming a stuck queue, or recovering from a usage limit.
  T3 Tots uses the internal API for that gap, and says it will move onto the official interfaces as they
  catch up.
- **What v1.4.34 actually changed:** the post lists everything since v1.4.30 (Oct 29). The project-bot
  feature Iris named landed in v1.4.33, not in v1.4.34. One listener can send to several bots. The main bot
  gets everything until you unsubscribe it. Another bot gets only the projects or event kinds it is
  subscribed to (`t3listen bot add --project`, `t3listen bot add --events failed`). A slow bot does not hold
  up the others. v1.4.31 and v1.4.32, also in that span, quiet the phone: filters on what a run's last reply
  says, failures that arrive together sent as one message, and a cap so a long outage does not flood the
  bot. v1.4.34 itself is about skills, not the listener. First setup now saves every skill in full instead
  of downloading one on each use. An update no longer replaces a skill you edited without asking (keep
  mine, take the new one, or merge). Setup asks once whether to tell you first, update on its own, or not
  check. No tool script changed in v1.4.34.
- **What we checked:** the v1.4.34 tag, its release notes, the README at that tag, and the licence field on
  the repo (MIT). Nothing is installed here. Saturn's T3 Code is a Nov 13 nightly of 0.1.10, and the
  companion's own scripts are not on the machine.
- **What it would take here:** Saturn, beside T3 Code. No GPU, no container, no new model. It needs Node 22
  and Python 3.8, which a host already running T3 Code has. The scripts and skills are small. Turning on
  `t3listen` is the only new piece: a login service that posts to a webhook you choose. On Linux the
  "stay quiet while you are at the desk" setting does nothing (macOS and Windows only), so a listener here
  would ping on every event you have not filtered. A T3 Code update can break the tools, because they use
  the internal API. Saturn is on a Nov 13 nightly of 0.1.10, so that risk is current, not theoretical.
- **Value and risk:** the useful gap over the official MCP is live questions and approvals on a phone, a bot
  per project, and usage-limit recovery. We already handed the official MCP connector to the owner of T3
  Code on Nov 11, and we already have our own session mail between agents, so this does not fill a hole in
  the lab. The risk is an unofficial API on a nightly, plus an outbound webhook if the listener is turned
  on. That webhook is a network choice, not something to switch on from a bookmark.
- **Verdict: watch.** Not installed, no download, no test case. Passed to the owner of T3 Code to decide
  whether the gap over the official MCP is worth the unofficial API. If it is tried, the listener stays off
  until that owner picks a webhook, and nothing is bound beyond the local machine.
