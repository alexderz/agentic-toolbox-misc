## Unsloth Dynamic V3.1 GGUFs for Qwen3.8-27B: standard comparison

- **What it is:** Unsloth re-uploaded [unsloth/Qwen3.8-27B-GGUF](https://huggingface.co/unsloth/Qwen3.8-27B-GGUF)
  with its Dynamic V3.1 recipe. Unsloth claims a 5 to 10% higher average on Terminal Bench, DeepSWE and others
  than its previous quants. The repo also gains an MTP draft head (`MTP/mtp-Qwen3.8-27B-Q4_0.gguf`).
- **What we checked:** revision `4af51b35` (Apache-2.0). We already serve Unsloth's pre-V3.1 UD-Q4_K_M from
  September. The new UD-Q4_K_M is a different file: 16,564,259,744 bytes against our 16,464,440,224.
- **Test:** an A/B on the 3090 where the only variable is the file. Both rows use the same llama.cpp build, flags,
  250 W power limit, 96K context and q8_0 K/V. Each pair gets a speed benchmark on prose, code and JSON, a quality
  check and needle retrieval at 30K and 90K (`0j8` for the old file, `0j9` for V3.1). Unsloth's claim is about
  agentic coding, so each file also runs our agent test 1. That test has a coding agent (OpenCode in a sandbox)
  build a Home Assistant command-line tool from a spec, with Qwen's thinking sampling (`0ja` old, `0jb` V3.1).
- **Started:** V3.1 UD-Q4_K_M downloaded and SHA-256 verified; all four cases queued.
- **Results:** pending. Numbers will be added here.

## Nex-N2.6 (Nex-AGI): viability test

- **What it is:** [nex-agi/Nex-N2.6](https://huggingface.co/nex-agi/Nex-N2.6) (Apache-2.0), a multimodal agentic
  model for computer use, coding and long tool-use tasks. It is a post-train of GLM-5.3-Flash (`glm5_next`,
  about 321B parameters, MoE), published as FP8 safetensors (328 GB). The vendor reports OSWorld 83.0 and
  Terminal-Bench 2.1 84.1.
- **What we checked:** Bartowski published imatrix GGUFs
  ([bartowski/Nex-N2.6-GGUF](https://huggingface.co/bartowski/Nex-N2.6-GGUF), revision `e7959c74`) from IQ1_S
  (74.9 GB) up to Q8_0 (341.5 GB), plus a vision projector. GLM-5.3-Flash support has been in upstream llama.cpp
  since late September, and our llama.cpp build contains it.
- **Fit:** this is the "experts in RAM" tier. Q2_K is 125.67 GB: about 50 GB sits on the two cards and the rest
  of the experts run from RAM. That is the same quant level as the GLM-5.3-Flash Q2_K we tested before, so the
  rows compare. Q3_K_M (155 GB) is technically under our ~160 GB ceiling, but it would leave about 10 GB of
  Titan's RAM free, too tight to run cleanly.
- **Started:** Q2_K and the f16 vision projector are downloading (127 GB, throttled, SHA-256 checked). The
  viability case `0je` is ready to queue once the download verifies. It runs llama.cpp on both cards, and the
  engine places the experts itself with a 2 GiB VRAM margin per card. It checks fit, then runs the oracle, the
  speed benchmarks, the quality check and retrieval at 30K and 90K. The image row waits until our runner has an
  image stage. If it is viable, the agent tests follow.
- **Results:** pending.
