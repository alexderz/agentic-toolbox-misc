### SenseNova-Loop-9B (SenseTime): backlog, worth a viability run later

- **What it is:** a 9B "looped" transformer: 32 stored decoder blocks, of which blocks 4 to 27 run twice, so each token
  passes through 56 layers (about 14.6B parameters' worth of compute from 9B of weights). Two residual streams mixed
  by a small router (mHC), hybrid linear/full attention (3:1), up to 512K context, text and image input.
  [Model](https://huggingface.co/sensenova/SenseNova-Loop-9B) · [code](https://github.com/OpenSenseNova/SenseNova-Loop) ·
  [post](https://x.com/TeksEdge/status/2122729064293368139).
- **What we checked:** the final release is Apache-2.0 (revision `329a65f7`, ~18.9 GB BF16) behind an auto-approve
  Hugging Face gate, with custom modelling code. The benchmark claims (Terminal-Bench 2.1 59.55, NL2Repo 41.36,
  GAIA 69.90, close to Qwen3.8-27B) are the vendor's, not ours.
- **Engines:** stock llama.cpp cannot run it yet (feature request #31571 is open). SGLang PR #47281 and vLLM PR #64832
  are open, unmerged. A community llama.cpp fork
  ([GuideboardLabs/llama.cpp-sensenova-loop](https://github.com/GuideboardLabs/llama.cpp-sensenova-loop), MIT, head
  `a7f77a78`) adds the architecture and, as of today, CUDA kernels for the mHC router. Ungated text-only GGUFs of the
  final release from the same people: [guideboardlabs/SenseNova-Loop-9B-GGUF](https://huggingface.co/guideboardlabs/SenseNova-Loop-9B-GGUF)
  `5cf78603` (Q8_0 9.54 GB, Q4_K_M 5.63 GB). The looped block is stored once and reused, so the file is small.
- **Local fit (on paper, not measured):** Q8_0 plus an 8-bit KV cache at about 100K context fits either of our cards
  with room to spare. Looping saves memory, not compute: expect decode speed closer to a 15B model than a 9B one.
- **Plan when testing resumes:** build the fork pinned at its commit for both card generations, pull the Q8_0, then the
  standard new-model viability case (fit, speed and time to first token, ~100K retrieval, quality, coding and an agent
  test). Text-only rows: the GGUF has no vision tower.

### NVIDIA Qwen3.5-4B → Qwen3.8-27B draft model: backlog, good speed experiment

- **What it is:** a full 4.2B model (Qwen3.5-4B base) trained to imitate Qwen3.8-27B's output distribution, for
  speculative decoding: the small model proposes a block of tokens and the 27B checks them in one pass.
  [Model](https://huggingface.co/nvidia/Qwen3.5-4B-Qwen3.8-27B-Draft) (`bc5ad93d`) ·
  [GGUF](https://huggingface.co/bartowski/Qwen3.5-4B-Qwen3.8-27B-Draft-GGUF) (`6e5f6f85`, Q8_0 4.48 GB).
- **What we checked:** licence is the NVIDIA Open Model Agreement (commercial use allowed, global). The card's
  acceptance numbers (block of 16, rejection sampling) beat the model's own multi-token-prediction head by about 38%
  on coding; the post says 46% overall. It was trained on sequences up to 12K tokens, so long agent prompts are the open
  question. NVIDIA tested it on vLLM; llama.cpp's draft acceptance works differently, so its numbers won't carry over
  one-to-one.
- **Plan when testing resumes:** rerun our existing Qwen3.8-27B Q4 baseline (3090, 96K context) with this draft on the
  second card, against the plain run and our existing MTP and DFlash2 rows; check exact output equality at
  temperature 0 and tokens/s at short and long prompts.

### Living Weights (TensorFold): watch, no path on our cards

- **What it is:** an experimental TensorFold feature (`--slide`): tell a running model a fact and it writes about ten
  new neurons into the checkpoint's own weight files, so the fact survives restarts and moves with the folder. It keeps
  a snapshot so all lessons can be rolled back. [Docs](https://github.com/ashhart/TensorFold/blob/main/docs/living-weights.md) ·
  [post](https://x.com/ashxhart/status/2122601492439847023).
- **Local lens:** learning runs only on Apple silicon and NVIDIA GB10 boxes, not on an RTX 3090 or V100; serving
  without `--slide` is unchanged. The project's own notes say related facts can interfere and recall drops past a few
  dozen facts. TensorFold 1.2.8 and 1.2.9 are out (1.2.9 adds an experimental v2 controller); we serve 1.2.7, and
  checking the newer releases waits until testing resumes.
